# 全局 Git Commit Skill 设计

## 目标

创建用户级 `git-commit` skill，为不同技术栈的 Git 仓库提供一致、安全的专业提交流程。skill 应自动识别仓库约定，将多个逻辑变更拆为原子提交，并默认采用 Conventional Commits。

## 范围

- 安装到用户级 Codex skills 目录，使其对所有仓库可用。
- 支持提交当前改动、整理原子提交以及修正尚未推送的提交。
- 根据改动范围执行已有的相关验证。
- 默认只创建本地提交，不执行 push 或创建 PR。

以下内容不在范围内：为每个仓库安装 commitlint 或 Git hooks、自动发布、自动创建 PR，以及修改已推送历史。

## 方案

采用纯指令型 skill，由精炼的 `SKILL.md` 定义决策与安全流程，并通过 `agents/openai.yaml` 提供 Codex UI 元数据。不引入 Shell 脚本或外部依赖，以保持跨平台和跨技术栈兼容性。

仓库已有的 hooks、commitlint、测试和静态检查仍然是机械约束的来源；skill 负责理解变更语义、选择验证命令并组织提交。

## 规范解析

提交规范按以下优先级解析：

1. 用户当前指令。
2. 适用范围内的 `AGENTS.md`、`CONTRIBUTING.md` 及仓库文档。
3. 近期提交历史体现的稳定风格。
4. 默认 Conventional Commits。

默认提交格式为：

```text
<type>(<scope>): <中文描述>
```

`scope` 可省略。默认类型包括 `feat`、`fix`、`docs`、`refactor`、`test`、`build`、`ci` 和 `chore`。如果仓库明确使用其他语言或格式，则遵循仓库规范。

## 工作流

1. 确认仓库根目录、当前分支、远端跟踪关系和工作区状态。
2. 阅读适用的仓库约定，并检查近期提交风格。
3. 查看 staged、unstaged 和 untracked 改动，识别用户已有暂存意图。
4. 排查疑似凭证、私钥、大型产物、依赖目录和其他不应提交的生成文件。
5. 按功能目的和依赖关系划分逻辑变更；不同目的的改动创建不同提交。
6. 为每组改动选择最小且相关的测试、类型检查、lint 或构建验证。
7. 使用显式文件路径分组暂存，复核 staged diff 后创建提交。
8. 重复分组、验证和提交，直至处理完用户授权范围内的改动。
9. 核对提交历史、工作区和远端关系，并向用户报告 commit SHA、信息及验证结果。

## 原子提交规则

- 每个提交只表达一个可独立解释的目的。
- 测试优先与其验证的实现放在同一提交，除非仓库明确采用独立测试提交。
- 纯文档、重构和工具链改动与功能变更分开，但紧密依赖且拆分后会破坏构建时可以合并。
- 不把来源不明或与当前请求无关的改动纳入提交。
- 尽可能使每个提交保持构建与测试可通过。

## Amend 规则

仅在同时满足以下条件时自动执行 `git commit --amend`：

- 目标提交确认尚未存在于其跟踪远端；
- 新改动与目标提交属于同一逻辑目的；
- amend 不会覆盖其他作者或用户未授权的工作。

无法确认远端状态、提交已经推送或逻辑目的不一致时，创建新提交。任何修改已推送历史的操作都需要用户另行明确授权。

## 安全与失败处理

- 默认禁止 push、force push、reset、rebase、删除文件和修改已推送历史。
- 不使用宽泛暂存掩盖文件边界；提交前必须复核 staged diff。
- 发现疑似敏感信息、异常大型文件、冲突或来源不明的改动时停止并报告。
- 相关验证失败时不创建该组提交，保留现场并报告失败命令与关键信息。
- 缺少工具或依赖时先报告；仅在安装属于当前请求的正常范围时执行安装。
- Git hook 拒绝提交时保留 hook 输出，不绕过 `--no-verify`。

## Skill 结构

```text
git-commit/
├── SKILL.md
└── agents/
    └── openai.yaml
```

`SKILL.md` 包含触发描述、规范解析、分组提交工作流和安全边界。`agents/openai.yaml` 仅包含 `display_name`、`short_description` 和显式引用 `$git-commit` 的 `default_prompt`。

## 验证策略

1. 使用官方 `quick_validate.py` 检查 skill 名称、YAML frontmatter 和目录结构。
2. 检查以下代表性场景能否从指令中得到唯一、安全的行为：
   - 单一逻辑变更创建一个提交；
   - 多个逻辑变更自动拆分为多个提交；
   - 验证失败时停止提交；
   - 未推送且同目的的提交允许 amend；
   - 已推送提交禁止自动 amend；
   - 用户未要求时禁止 push；
   - 疑似敏感文件停止并报告。
3. 检查 UI 元数据与 `SKILL.md` 的名称和用途保持一致。

## 完成标准

- skill 安装到用户级目录并能被 Codex 自动发现。
- 官方校验脚本通过。
- 代表性场景检查全部满足设计约束。
- 不修改项目依赖或 Git 全局配置。
